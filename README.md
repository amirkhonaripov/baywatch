# BayWatch: the service-floor website

**Live:** https://amirkhonaripov.github.io/baywatch/

The web app for **BayWatch** (team DNA), a computer-vision system for a car dealer's service department. A service manager sees:
- every camera in the service centre: real public footage that our models analyse live, plus simulated bays;
- a 3D floor showing where every car is and what each bay is doing;
- KPIs and alerts, with an "AI monitoring Off / On" comparison;
- one tracked visit, from the gate to the handover, with an events strip that jumps between its steps;
- the work-order check: for each paid line, evidence found, not observed, or not camera-verifiable.

Every camera accepts **your own photo or video**. It is sent to the BayWatch API, and the result shows:
- the boxes the models found;
- which models ran and which were skipped, and why;
- the server time and the model versions.

The models, the pipeline, the API and all evaluation code live in **[baywatch-core](https://github.com/amirkhonaripov/baywatch-core)**. This repository holds only the website.

## Run it locally
Requires Node 20 or newer.
```bash
npm ci
npm run dev                                   # http://localhost:5173, uses the API at http://localhost:8008
```
To use another API, add `?api=` to the URL, for example `http://localhost:5173/?api=https://sanjar--seen-api.modal.run#/console`. Alternatively, build with `VITE_API_BASE=<url> npm run build`.

To run the API yourself, see the baywatch-core README. It covers installing, downloading the weights, and `python -m serve.local`.

## Recorded outputs for the built-in samples
`public/precomputed/` holds the real API output for every built-in camera sample, so the demo opens instantly. The AI log says "recorded from our API on <date>", and "Run again" always makes a live call. Uploads are never pre-recorded.

To re-record against any running API:
```bash
node scripts/precompute.mjs http://localhost:8008
```

## What is real and what is simulated
- Cameras marked **Live AI** send real footage to the real models on every call; the AI log shows the call.
- The bays marked **Simulated** show Blender renders. The other customers' cars ("background traffic") come from the scenario engine in baywatch-core (`sim/day.py`). Both are labelled as simulated on screen.
- The Results page shows `public/eval_report.json`, which is generated by `eval/run_all.py` in baywatch-core.

## Layout
| Path | Contents |
|---|---|
| `src/pages/Console.tsx`, `src/console/` | The service floor: cameras, 3D floor (react-three-fiber), KPIs, alerts, events, uploads |
| `src/pages/Metrics.tsx` | Results page (reads `public/eval_report.json`) |
| `src/pages/About.tsx` | Data and licences (reads `public/data_sources.json`) |
| `src/contracts.ts` | Types generated from the JSON Schemas in baywatch-core (`scripts/codegen.sh` there) |
| `src/lib/sampler.ts` | In-browser video sampling: a clip is read as 16 frames; only JPEG frames are uploaded |
| `public/stages/`, `public/arrivals/` | Example footage (credits on the Data page) |
| `public/day/floor.json` | Simulated background traffic, generated by `sim/day.py` in baywatch-core |
| `public/models/` | Low-poly car and person models (Kenney, CC0) |

## Deploy
`.github/workflows/pages.yml` builds and publishes to GitHub Pages on every push to `main`. Set the repository variable `SEEN_API_BASE` to the API URL.
